# Serial task execution

Before the first model request, execution captures the project's package manager and existing script definitions through the authorized Tool Runtime. Reads use the same approval mode, tool budget and durable audit events as other operations. Verification permits additional checks, but deletion or modification of any original script (including indirect helper scripts) or package-manager declaration stops automatic acceptance and persists `needs_review`. Legitimate script changes therefore require explicit inspection under this conservative first-version policy; the engine does not silently approve a weaker replacement. A project without a manifest may create one, and the first discovered definitions then become the execution's baseline. Existing unreadable, oversized, truncated or invalid manifests fail explicitly.

An execution creates a bounded task plan before enabling tool calls. The planner receives the user's goal and no tools. Its output must be a bare JSON array of one to twenty pending tasks containing unique IDs, dependency IDs, titles and nonempty objective acceptance descriptions. Runtime schemas reject malformed JSON, missing dependencies, cycles, duplicated dependencies, precompleted states and tool calls during planning. A trusted caller can supply `ExecutionOptions.plan`; it passes the same validation.

The TaskGraph schedules one available task at a time. Each task runs through the Agent Runtime and then independently discovered project checks. Only successful project checks allow a task to become completed and unblock a dependent task. A final task's project checks gate the execution's final delivery. Plans must therefore describe independently verifiable increments; splitting a change into intermediate non-building fragments causes that step to fail and enter bounded repair. Verification currently discovers Node package scripts. Acceptance text helps guide the implementation but is not an executable proof of every natural-language requirement.

Planning, Agent turns, all model tools, discovery reads, verification commands, retries and repairs share an execution budget. A model delivery alone never marks a task complete. Approval denial, cancellation, timeout and exhausted budgets stop recovery. Each verification tool's intent and result are persisted before/after execution and are returned in event sequence order. Verification currently returns its queued audit events after its promise resolves; approval callbacks remain available while it is running.

SQLite event/snapshot writes are transactional. An event is returned only after its snapshot and event have been saved together. A failed save ends execution instead of attempting to append with a skipped sequence. A stopped active state or an unmatched tool intent recovers into `needs_review`; tools with unknown side effects are never automatically replayed. Plans and task transitions are durable events, and active steps require review after restart rather than being silently rerun. Saved and requested workspace paths are both resolved through realpath before resume comparison, so Windows short names and junction aliases of the same directory are accepted. The persisted workspace identity remains unchanged; different directories and providers are still rejected. Local workspace lock files prevent concurrent executions. A leftover lock requires inspection; automatic stale-lock removal is intentionally unavailable. This is controlled execution using the current OS account, not an operating-system sandbox.

Known environment credential values and recognizable bearer/API token forms are redacted before presentation, model history reconstruction and persistence. Text deltas retain a bounded tail so credentials fragmented across model chunks are not exposed as separate prefixes. This is defense in depth, not a guarantee that arbitrary user secrets can be identified. Permission mode comes only from the trusted execution options or validated session state. Historical system messages are replaced with the engine's own prompt when a new Agent loop starts.
