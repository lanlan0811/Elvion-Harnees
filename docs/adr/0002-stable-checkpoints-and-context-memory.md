# ADR 0002：稳定检查点与受限上下文压缩

- 状态：采纳（补齐已批准 Phase 1 计划的恢复与上下文保留要求）
- 日期：2026-11-15

## 背景

初版能够恢复 SQLite 消息和事件，但活动执行一律要求核实，稳定任务仍会重新规划；上下文仅截取最近完整工具交互，旧决策可能因预算而消失。这未达到原计划的重启继续和压缩后保留关键决策要求。

## 决策

- 在原 `schemaVersion: 1` 快照中增加可选、独立 `version: 1` 的 execution checkpoint。旧数据继续读取；旧活动会话没有检查点时不推断安全状态。旧版程序不能读取新增字段，应升级后再使用新会话文件，不做静默降级迁移。
- Checkpoint 保存原模型、TaskGraph、当前任务、验证脚本基线、客观报告与累计预算。继续原任务时不重新规划、不扩大预算、不修改保存权限；已完成会话仅返回原报告。
- 稳定边界包括完整工具批次、已结束的模型交付、完整验证结果、任务之间。每次模型调用（包括压缩）与工具执行前先保存已消耗预算和 intent。未确认调用或不完整批次进入 `needs_review`；终态失败、取消、超时不自动重启。
- 保留工作区互斥锁策略。进程崩溃的遗留锁要求人工核查，不通过自动删锁冒充容灾；正常关闭迭代器并重启可直接继续稳定检查点。
- Context Engine 将超预算的旧完整交互分块、受限地概括为 decisions/completed/remaining，原目标和验收条件保留原文。摘要必须严格校验并作为 user 层不可信历史数据；不改变系统规则、权限或客观验收结论。
- 压缩不调用工具，不引入外部存储或依赖；每次请求消耗同一模型 Turn/时间预算。取消、断流、畸形摘要、超大单次交互和无法放入预算均明确失败，不无声丢弃历史。
- 自动规划前，通过同一 Tool Runtime 读取有界文件清单与根目录、局部 AGENTS/项目说明，不把整个仓库注入上下文。分析结果作为不可信项目数据传给规划器，显式受信任计划无需重复分析。审批请求、等待状态及决定以唯一 ID 持久化；批准不会成为后续调用的通用授权。

## 备选与影响

从事件临时重建全部状态易遗漏验证基线和累计预算；直接重跑会重复副作用。可选版本化检查点使边界明确，事件仍保留完整审计。模型摘要可能遗漏或误述历史，因此不能作为已验证事实或权限来源；当前文件与独立检查仍优先。大交互不能完整放入预算时停止，后续可在不改变安全语义的前提下改进相关性选择。

## 验证与回滚

通过真实 SQLite 关闭/重开、实际文件/进程/验证计数、无重复工具、累积预算、未知批次、原脚本变更与模型匹配回归。上下文测试覆盖重复压缩、取消、非法输出、工具交换完整性及请求前预算持久化。回滚代码时保留用户数据；新检查点会话不可交给不认识该字段的旧程序写入。
